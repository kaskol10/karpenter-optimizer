## [Unreleased]

### Added
- **Generic cluster-wide Log Explorer** (replaces the Karpenter-only analyzer): pick any pod in the cluster and read/analyze its logs. New endpoints behind the standard `/api/v1` auth: `GET /api/v1/pods` (compact pod summaries — status, readiness, containers, restarts, Karpenter flag — for the picker), `GET /api/v1/pods/logs?namespace=&pod=&container=&tailLines=&sinceSeconds=&previous=` (any pod/container, no Karpenter gate — the dedicated `GET /karpenter/logs` keeps its `app.kubernetes.io/name=karpenter` gate), and `POST /api/v1/logs/analyze`, which parses a Karpenter JSON log line with the existing Karpenter analyzer first and otherwise runs a **generic** analyzer: an LLM explanation when configured, else a built-in heuristic classifier (OOM, image pull, crash loop, permission/admission, network/dependency, disk pressure, app panic, generic error) with per-pattern recommendations. The frontend is a new `LogExplorer` (pod picker with Karpenter presets, container/tail/since/previous controls, client-side error filter, search with match highlight + prev/next, and Analyze selection / last-N / all-errors buttons) that replaces `KarpenterLogAnalyzer`. Other tabs deep-link into it via a `seedPod` ("namespace/name" or "namespace") — e.g. a Workloads row's **Logs** button pre-filters the picker to that workload's pods.
- **Workloads tab honesty fixes**: the "CPU Used"/"Memory Used" columns are relabeled **CPU Total (requests)** / **Memory Total (requests)** (the data is summed pod resource requests, not live usage — the card description now says so); the spec request/limit columns are relabeled "(spec)" and normalized to the same cores/GiB units; the summary strip is computed over the **full filtered set** (not just the current 50-row page) and labeled "Filtered total (N workloads)"; namespace is now a **dropdown** of unique namespaces (plus the name text filter); each row gains a **Logs** deep-link into the Log Explorer; and an "Updated HH:MM:SS" stamp sits next to Refresh.
- **Disruptions tab clarity fixes**: the 1h/6h/24h/7d window selector is moved next to **Recently Terminated** and labeled "History:" (it only ever windowed that list — the header now reads "Active node disruptions, sampled live"); **Drift** (orange) and **Expiration** (amber) are split out of the conflated "Expiration/Drift" bucket (filter and summary badges); relative timestamps keep their text but expose the **absolute UTC time on hover**; when disrupted nodes can't be priced the "still billed" banner is replaced by an explicit **"cost unknown (pricing unavailable)"** notice (the summary now carries `costUnknown` from the backend); and the blocked banner gains a one-line gloss defining *blocked* (a PDB reports 0 disruptions allowed) vs *blocking pods* (pods held by a PDB).
- **Recommendations: two surfaces, clearly labeled.** Overview's CTA is now **"Run cluster-wide scan"** (tooltip explains it uses the live cluster summary) plus a cross-link **"Prefer AI Agent plans with strategy selection →"** into the Recommendations tab; `AgentRecommendations` describes itself as strategy-based AI plans and links to a **"How these numbers are made"** popover (live AWS Pricing API on-demand price, spot = 25% estimate, region+architecture candidate filter, 1–3 type combinations, >10% cost-increase filter, and that "Confidence" is an LLM self-assessment — indicative only, which the confidence badge's tooltip now also says).
- **NodePoolCard correctness fixes**: the in-place `currentInstanceTypes.sort()` mutation of React state is gone (comparison and display copy the array); recommended instance types render **symmetrically** with per-type node counts (`r6g.xlarge (12)` — an even split of the recommended node total, matching the cost model's allocation) to line up against the current `type (N)` badges; GPU detection is widened to the real family set (`g4|g5|g6|p2|p3|p4|p5|trn|vt1|inf2|dl1|ml1`, base-type aware) and the red "GPU instances detected" alert becomes a **neutral info alert** explaining GPU instances are far more expensive and require GPU-using workloads; the green "changes recommended" border/badge is **green only when the recommendation actually saves money** (amber + "Changes recommended" otherwise); and `currentCostUnknown` renders the current cost as a clearly-marked **partial sum** with a "pricing unavailable" hint (and suppresses the savings figure, which can't be computed honestly) instead of letting `$0/hr` imply free.
- **Opt-in API authentication** (`API_AUTH_TOKEN`): when set, every `/api/v1` route except `/health` (k8s probes) and, when enabled, `/metrics` requires `Authorization: Bearer <token>` (constant-time compare). Unset = legacy open API with a startup warning — zero migration pain, hardening is opt-in. Chart: `config.apiAuthTokenSecret` (existing Secret, key `api-auth-token`) or `config.apiAuthToken` (dev-only plain). The frontend container receives the same token as `REACT_APP_API_TOKEN` via the runtime `config.js` (never baked into the bundle) and sends it through an axios default header, so enabling auth does not 401 the UI.
- **Chart secrets for credentials**: `LLM_API_KEY` (`config.llm.apiKeySecret`, key `api-key`) and alert channel URLs (`alerts.urlsSecret`, key `urls`) are now delivered via `secretKeyRef` so they are not visible in the pod spec / etcd. Plain `config.llm.apiKey` and `alerts.urls` remain as documented dev-only fallbacks.
- **Graceful shutdown**: the API now runs under `signal.NotifyContext(SIGINT, SIGTERM)` with `http.Server.Shutdown` (10s drain) instead of a blocking `gin` run; background samplers take a root cancellable context and the durable Postgres pools (`gatewayhistory`, `servingdurable`) are closed on shutdown.
- **Alerting engine** (opt-in): a background evaluator runs on each 60s sampler tick and watches five conditions — **cost spike** (cluster cost/hour up >X% vs its trailing 24h average), **blocked disruption** (a node stuck blocked for >N min), **serving under pressure** (KV cache ≥X% held for the `for` duration), **gateway** (503 rejections or error rate above threshold), and **serving pod offline**. Each condition drives a `pending → firing → cleared` state machine with a held-clear window so flapping does not spam; the firing set is **persisted to disk** so restarts neither re-fire nor drop in-flight alerts. New transitions fan out (one message per channel per transition) to **ntfy** (topic URL + priority/tags), **Discord** webhook, **Slack** incoming webhook, or a **generic JSON webhook** (`{source, status, severity, title, alerts[]}`); an optional `remindWhileFiring` (1h/4h/12h/24h) re-notifies while an alert stays firing. All outbound URLs are **SSRF-validated** (http(s) only, no redirects, no response bodies logged, resolve-then-pin, refuse link-local/metadata/multicast) and treated as **credentials** — `GET /api/v1/alerts/config` masks channel URLs (host kept, path redacted to `/*`) and `PUT` restores the stored URL by index so toggling a condition never wipes a secret. New endpoints: `GET/PUT /api/v1/alerts/config` and `POST /api/v1/alerts/test`. Chart values `alerts.enabled` + `alerts.urls` (or via the API), `alerts.stateFile`. Defaults to a conservative all-disabled config.
- **Prometheus `/metrics` exporter** (opt-in): a `GET /metrics` endpoint (text-0.0.4 via `client_golang`) serving `karpenter_optimizer_*` gauges — `up`, `kubernetes_connected`, `karpenter_detected`, cluster nodes/pods/CPU/memory used & allocatable, cost/hour, power watts, per-NodePool `nodepool_nodes` + `nodepool_cost_per_hour`, per-serving-pod online/KV-cache/TTFT-p95/E2E-p95/tokens-per-sec/requests-per-sec, gateway in-flight/queued/rejected/error-rate/requests-per-sec/spend-total/per-app-spend, and disruptions active/blocked/cost-per-hour. Data comes from an **atomic snapshot refreshed by the existing samplers** (cluster, serving, gateway, alert ticks), so a scrape performs **zero** extra Kubernetes or AWS Pricing API calls. Gated by `METRICS_ENABLED` (chart value `metrics.enabled`); the route is not registered and `/metrics` 404s when off. The chart's optional `serviceMonitor` scrapes `/metrics` when both `serviceMonitor.enabled` and `metrics.enabled` are set.
- **Durable serving history** (opt-in): per-pod serving samples are now optionally persisted to **Postgres/CNPG** in a new `serving_history` table (`(pod_key, t)` upsert, retention index, retention purge) when `SERVING_HISTORY_DSN` — or the existing `GATEWAY_HISTORY_DB_HOST/PORT/USER/NAME/PASSWORD` parts (reuse one CNPG instance) — is set. The in-memory `servinghistory.Store` stays the fast path for the 1h/6h/24h sparklines; the durable store serves the new **7d** trend window (closed period read from Postgres, today merged from live samples, in-memory points winning on overlap). `GET /api/v1/serving/history` gains `window=7d` when the durable store is active, otherwise windows remain in-memory. Chart values `servingHistory.durable` + `servingHistory.retentionHours`. Also fixed `parseGatewayHistoryWindow`/`parseServingHistoryWindow` to accept `Nd` day windows (`7d`/`14d`/`30d`).
- **sparkDash-grade visual polish** (light scope):
  - **Dark/light theme** (4a): a sun/moon toggle in the header persists to `localStorage`, defaults to system preference via `matchMedia`, and `index.js` applies the `dark` class to `<html>` **before first paint** (no flash). A token audit replaced hardcoded light-only utilities (`bg-white`, `text-blue-600`, `border-gray-*`, `bg-purple-100`, `text-gray-900`, …) with semantic tokens (`bg-card`, `text-primary`, `border-border`, `text-foreground`, `bg-muted`) across the header/nav, cards, tables, and the gateway/serving components.
  - **Shell/nav polish** (4b): the 8 copy-pasted tab buttons were extracted into a `NavItem` component with a lucide icon per tab (Overview, Nodes, Topology, Serving, Workloads, Disruptions, Recommendations, Logs); the active tab keeps the `primary` underline with a `hover:bg-muted/40` state, a **live disruptions count badge** appears on the Disruptions tab, and `<main key={activeTab}>` runs a subtle fade/slide-in page transition.
  - **Empty/loading states** (4c): a shared `EmptyState` (icon + title + hint + optional retry) and `Skeleton`/`SkeletonRows` (radix-free pulse divs, no layout shift) now replace ad-hoc "no data" strings and generic spinners across GlobalClusterSummary, NodeUsageView, WorkloadUsageView, TopologyView, DisruptionTracker, AgentRecommendations, KarpenterLogAnalyzer, and ServingHealth — error banners carry a retry button.
- **LiteLLM Gateway cost & token history** (Serving tab): per-day spend and token usage for the LiteLLM gateway, so you can follow cost trends over time instead of only seeing cumulative totals. Days are **UTC (00:00–23:59)** and the UI is a **usage-by-day dashboard**: a **stacked per-day bar chart** (one bar per day, split by the active **Split by** dimension — app / API key / team — with a spend/tokens toggle and an optional daily-total line) plus a **per-day table** (day / spend / tokens / top consumer, today marked "so far"). A background sampler (same 60s interval as the cluster/serving trend samplers) diffs the gateway's cumulative spend/token counters each tick and folds the deltas into per-day totals in the store — **incremental rollups, no midnight job**: once a day passes its row is final and is only ever read from the store (the gateway is never re-queried for closed days), and today updates live. The chart is **interactive**: series are colored on a single-hue violet ramp **ranked by usage** (darkest = biggest consumer), and hovering a series (bar segment or legend chip) highlights it across all days with a soft gradient area under its evolution curve, dims the other series, and opens a **rich tooltip** (series value, % of day, % of window, day total) plus a **live stat strip** (window total, share, avg/day, today-vs-average delta); the chart legend is a row of **pill chips** with each series' window share, and clicking a chip pins the highlight. New endpoint `GET /api/v1/serving/gateway/history?split=total|app|apikey|team&window=14d` returns `{window, split, store, days[]}` (each `day` has `value` + `spend` + `tokens`, ordered by day; 7/14/30-day window selector). Counter resets (a gateway replica restart) clamp the interval diff to 0 rather than reporting a spike (the day is an honest under-count).
  - **Storage**: in-memory by default (resets on process restart), or a durable **Postgres/CNPG** store when `GATEWAY_HISTORY_DSN` (or the `GATEWAY_HISTORY_DB_HOST/PORT/USER/NAME/PASSWORD` parts) is set — the Helm chart provisions a small CNPG `PostgresCluster` when `database.enabled: true`, making history survive restarts/redeploys (and enabling multi-replica consistency). Retention via `GATEWAY_HISTORY_RETENTION_HOURS` (default 720 = 30 days). Requires the CNPG operator to be installed when enabled; if the DB is unreachable the app falls back to in-memory so the gateway UI is never blocked.
- **AWS China-region pricing**: AWS Pricing API queries now support `cn-north-1` and `cn-northwest-1` through the China partition endpoint, using the correct regional product location and CNY pricing. `/api/v1/config` exposes the configured AWS region and pricing currency, and pricing/recommendation responses include currency metadata for display.
- **Currency-aware cost display**: Cost figures throughout the UI now use the configured region's pricing currency (`CN¥` for China regions, `$` otherwise), including cluster summaries, recommendations, node usage, agent output, and disruption costs.
- **China pricing fallback snapshots**: Dated CNY fallback prices are used for supported China-region instance types only when live pricing is unavailable due to transient/API access failures; explicit no-product results are not masked by estimates. Pricing source metadata identifies regional fallback estimates.
- **Regional Pricing API routing**: Pricing requests prefer a global endpoint geographically suited to the target region (US, Europe/Middle East/Africa, or Asia-Pacific) and retry other global endpoints for transient failures while preserving the target product-location filter. China requests stay within the China partition. Pricing-index lookups also use region-appropriate hosts and filter results to the configured region.

### Fixed
- **NodePoolCard state mutation**: `currentInstanceTypes.sort()` sorted React state in place (and `recommendedInstanceTypes.sort()` alongside it), corrupting the source arrays across renders. The change-detection and instance-type lists now copy before sorting/comparing, and the "kept/removed" instance comparison matches on the base type so a current `m6g.2xlarge (27)` correctly recognizes a recommended `m6g.2xlarge`.
- **Workloads "Cluster totals" was page totals**: the summary strip reduced over the paginated 50-row slice, so totals silently changed as you flipped pages. It now reduces over the full filtered set.
- **Disruptions "live" title vs window selector**: the header claimed live state while a 1h/6h/24h/7d selector (which only affected "Recently Terminated") sat in the header; the selector is relocated and relabeled "History:" and the header reworded.
- **API test harness leak**: `setupTestServer` built a `Server` against the developer's real `~/.kube/config` and left background samplers running across tests; they read `s.k8sClient` (and the package-global LiteLLM prober) while other tests reassigned it — a data race surfaced under `-race`. The helper now starts a hermetic server (no cluster, no samplers).
- **`RecordOutcome` self-deadlock** in `internal/agent/learning.go`: the method held `historyMu.Lock()` while `saveHistory()`/`learnFromOutcome` re-took the same non-reentrant mutex, hanging the first `POST /agent/outcomes` forever. Persistence and learning now run outside the write lock (regression tests with timeouts in `internal/agent/learning_test.go`).
- **Release workflow clobbering the CNPG Postgres image tag**: `sed` over every `tag:` in `values.yaml` rewrote `database.cluster.postgresImage.tag` on the next release. App image tags are now bumped by repository-anchored replacement with a `postgresImage.tag` guard.
- **Swallowed pricing errors manufacturing fake savings**: pricing failures previously summed as `Cost: 0`, understating totals and faking savings (and skewing the cost-spike alert baseline). `/nodepools`, `/cluster/summary`, `/recommendations` (JSON + SSE), `/recommendations/cluster-summary`, and the history sampler now surface `costUnknown` when any node in a summed set is unpriceable; the cost-spike alert treats unknown-cost samples as no-data.
- **Cluster-wide pod-log dump**: `GET /api/v1/karpenter/logs` now requires the target pod to carry `app.kubernetes.io/name=karpenter` (403 otherwise), closing the hole left by the broad `pods/log` RBAC grant.
- **CORS wildcard + credentials anti-pattern**: removed `Access-Control-Allow-Credentials: true` combined with `*` (browsers reject it). Same-origin by default; optional single `CORS_ALLOWED_ORIGIN` for split deployments.
- **Per-request learning-agent construction**: the cost-optimization `LearningAgent` is now a process singleton (`sync.Once`), eliminating per-request history-file I/O, leaked initial `learnFromHistory` goroutines, and uncoordinated concurrent writes to `AGENT_HISTORY_FILE`.
- **Region-specific pricing estimates**: The `us-east-1` USD hardcoded/family estimates are no longer applied to other commercial regions or China. China costs are not presented using USD estimates, and unknown prices no longer silently understate mixed-instance totals as partial costs.
- **China fallback candidate availability**: Instance-type fallbacks now exclude families without regional China availability and include available AMD instance types when they are appropriate candidates.
- **Pricing-index architecture filtering**: AMD64 instance discovery now relies on AWS Pricing `processorArchitecture` metadata instead of instance-name substring matches, preventing x86 types such as `m6i.large` from being incorrectly excluded.

### Added
- **LiteLLM AI-Gateway Health** (Serving tab): when LiteLLM proxy pods are detected in the cluster (image or command contains `litellm`), the Serving view shows a **LiteLLM Gateway** card above the pod grid with fleet-wide stat tiles — in-flight requests, admission queue depth, 503 rejections, error rate, E2E p95 latency, gateway **overhead** p95 (time the gateway itself spends on a request, isolating it from model latency), and requests/s — plus a **per-model breakdown table** (req/s, requests total, error %, E2E p95, TTFT p95, tokens/s, cumulative spend). The card has an **Apps/Models toggle** (defaults to Apps) and a **Split by** control to group usage by **App** (`metadata_trace_name`), **API key** (`api_key_alias`) or **Team** (`team_alias`) — defaulting to App. Each split table breaks usage down by the chosen dimension (requests without a real value are grouped as `(unattributed)`) with total tokens split into input (prompt) vs output (completion), requests total, tokens/s, and cumulative spend — so you can see which apps, keys or teams are driving token consumption and cost. Each **model** row is also **expandable** to reveal which apps/keys/teams use that model (tokens in/out/total + spend) for the selected split dimension, surfacing the model→split relationship from the co-labeled token/spend series. New endpoint `GET /api/v1/serving/gateway` returns `{gateway: {...}}` (or `gateway: null` when no LiteLLM proxy is detected; the card then hides itself). Counters/gauges are summed across replicas, latency quantiles take the worst case, and rates come from counter diffs (nil until the second sample, 0 on counter reset). Compatible with LiteLLM v1.81.x and up, including the v1.81.x metric shape: request/failed counters are exposed with a `_total` suffix and labeled by the alias-prefixed `requested_model`, while spend/token/latency metrics are labeled by the base `model` — the prober bridges `requested_model → model` (via the token metric, which carries both) so request counts, error % and per-model req/s join correctly. The in-flight / admission-queue / 503-rejection tiles reflect whatever the gateway exports (absent on older versions, shown as 0). LiteLLM's `/metrics` requires auth since v1.85.0: set **`LITELLM_METRICS_API_KEY`** (Bearer token) to scrape it; a 401/403 surfaces an actionable banner hinting at that env var instead of failing silently. Built on the Prometheus parser shared with the vLLM/sglang prober (`llmhealth.Metrics`), which now keeps histogram buckets per label variant so per-model quantiles are correct.
- **Fleet Power Estimation**: The cluster summary now includes an estimated power draw (`power: {watts, coveragePct, nodeCount, coveredNodes}`) computed from a static wattage table keyed by EC2 instance family (GPU, general, compute, memory, storage families). The Cluster Overview shows an "Est. Power" tile (e.g. `~1.24 kW`, `4/4 nodes covered`) — clearly labeled as an estimate; nodes with unknown families are excluded from the total and from the coverage percentage.

Unreachable pods render as graceful offline cards (never an error). Results are cached 15s server-side to bound probe load. Note: requires the app to be able to reach pod IPs (in-cluster or pod-network reachability).

  - Automatic error categorization (Label Errors, Taint Tolerance, NodePool Limits, Resource Constraints)
  - AI-powered explanations using Ollama/LiteLLM (when available)

  - Visual display of error causes with severity indicators

- **Cluster trends (sparkDash-style)**: a background sampler (default every 60s) records cluster CPU/memory/GPU-memory/cost into an in-memory history store (default 6h retention, `HISTORY_INTERVAL_SECS` / `HISTORY_WINDOW_HOURS` env vars). New endpoint `GET /api/v1/history?window=1h|6h|24h`; the Cluster Overview shows a Trends row with CPU %, Memory %, GPU memory %, and estimated-cost sparklines (1h/6h/24h toggle). The Topology node header gains an "age" badge from the node's creation timestamp.
- **Serving model-usage ranking**: the Serving view now shows which models are the most used. A "Model usage (throughput)" ranked bar chart above the pod grid orders servers by `tok/s` with an active-load (running+waiting) indicator, and a sort control reorders the pod cards by Throughput / Active load / Name (online servers always first).
- **Serving E2E latency & request rate**: the vLLM/sglang probe now also parses `e2e_request_latency_seconds` (mean + p95 — whole-request latency, not just first token) and `num_requests_total` (→ `requestsPerSec`, a rate across samples, the truest "most used" measure). Both are gated on presence (hidden on older vLLM versions that don't emit them) and show on the pod cards; the sort control gains a "Requests/s" option.
- **Serving metric explanations**: the Serving view now explains its own numbers for users unfamiliar with LLM serving. Every card metric label (KV cache, Running, Waiting, Preempt, TTFT, E2E, Throughput, Load) has a hover tooltip with a one-line plain-English definition, and a default-collapsed "What do these metrics mean?" accordion at the top of the view covers each metric with what it measures and what to do when it looks wrong (e.g. sustained Waiting > 0 → overloaded, rising preemptions → memory pressure).
- **Serving per-server status verdict**: each online serving card now carries a one-glance status badge — **OK / Busy / Slow / Under pressure** — computed from all the card's metrics, with the specific reasons in a hover tooltip. Objective signals use absolute thresholds (preemptions or KV cache ≥ 85% → Under pressure; waiting requests → Busy); "Slow" is peer-relative (p95 E2E > 2x the fastest server running the *same* model, plus a 1s floor) since absolute latency thresholds are workload-dependent, with a loose TTFT fallback when no same-model peer exists.
- **Serving status: what it means and how to fix it**: the status badge tooltip now explains, in plain English, what each state means and lists concrete remediation steps (Under pressure → add GPU capacity / more KV cache via `--gpu-memory-utilization` or lower `--max-num-seqs`; Busy → add replicas / raise concurrency; Slow → check node placement & GPU contention, reschedule the pod). The "What do these metrics mean?" accordion documents the same guidance per state.
- **Serving placement**: each serving card now shows where the model runs — node name (click-to-copy), the node's EC2 instance type, and GPU model/count badge (e.g. `NVIDIA-H100 x8`). `GET /api/v1/serving` pods gain `node`, `nodeInstanceType`, `gpuModel`, `gpuCapacity` (enriched server-side from node labels, so the "check placement" fix hint is now actionable).
- **Serving historical traceability**: each serving card now shows per-metric trends (TTFT p95, E2E p95, KV cache %, throughput, requests/s) as sparklines over a selectable window (1h/6h/24h) plus a "last issue seen" marker — so you can see how a model behaved at a specific time, not just now. A background sampler (same 60s interval as the cluster trends) probes serving pods into a new in-memory per-pod ring buffer (`internal/servinghistory`, same retention as `HISTORY_WINDOW_HOURS`). New endpoint `GET /api/v1/serving/history?window=6h` returns per-pod `points` + `lastIssue` (last time the pod was offline / had queued requests / preemptions / KV cache ≥ 85%). History is in-memory only — it resets on app restart and fills from the first sample after launch.
- **Serving collapsible trends + GPU card UUIDs**: the per-card Trends section is now collapsible so cards stay at-a-glance — collapsed by default it shows a compact summary line (current KV cache %, throughput, and last-issue time) and the full 5 sparklines expand on click. Each serving card also now shows the specific physical GPU card(s) it occupies: a per-device badge (`83026582 · 44.0 GiB`, full UUID in the tooltip) parsed from the HAMi/KAI `hami.io/vgpu-devices-allocated` annotation. `GET /api/v1/serving` pods gain `gpuDevices` (only present on HAMi/KAI clusters; absent on standard whole-GPU pods).
- **Serving cards show the node hostname**: each serving card now shows the node's `kubernetes.io/hostname` label (e.g. `empathy1`) instead of the raw node name (e.g. `k3s` on a k3s node). `GET /api/v1/serving` pods gain `nodeHostname` (from the node label, falling back to the node name when the label is absent); `node` remains the node name and is still what the click-to-copy button copies (for `kubectl`).

### Fixed
- **Disruptions backend N+1**: `GetNodeDisruptions` no longer lists PDBs or `GET`s a pod per disrupted node. Pods for all target nodes are fetched in a single paginated list (grouped by node in memory) and PDBs are listed once cluster-wide; PDB selectors are parsed once. `EventCount` now reflects the real number of FailedDraining events per node (was hardcoded to 1), deleted-node entries group all of a node's events into one entry, and `NodeDisruptionInfo` gains `capacityType` (from the `karpenter.sh/capacity-type` label).
- **Inflated per-node GPU counts**: GPU count now prefers the `nvidia.com/gpu.count` node label over `Status.Capacity["nvidia.com/gpu"]` (which can be inflated by MIG/time-slicing, e.g. reporting 20 for a 2-GPU node). A debug log is emitted when the two disagree.
- **Topology per-GPU lanes merged distinct cards**: the per-device GPU lanes and pod device badges are now keyed by the HAMi device **UUID** (short UUID labels, full UUID in tooltips) because the allocated **index** in `hami.io/vgpu-devices-allocated` can be wrong (two pods on different physical cards both reported index 0).
- **Serving trends KV cache rounded to 0%**: the per-card trend sparkline and collapsed summary rendered KV cache with `toFixed(0)`, so any sub-5% usage (a lightly-loaded model) displayed as "0%" even though the live card shows it to one decimal. Both now use one decimal to match the live card, so low-but-nonzero KV usage is visible. (If KV still reads ~0.0%, the model's KV cache genuinely sits near empty — light load — not a bug.)

### Changed
- `kubernetes.Client.clientset` is now typed as `kubernetes.Interface` (was `*kubernetes.Clientset`) to allow fake-client injection in tests.
- **GPU overview under HAMi**: when HAMi is detected, the cluster overview, topology node badges, and node GPU gauges now lead with **GPU memory % in use** plus a **GPU pods** count (e.g. `NVIDIA-H100-NVL: 95% · 532.2/561.5 GiB (11 pods)`) instead of whole-GPU counts, which are meaningless for fractional GPU sharing. Non-HAMi clusters keep the count-based display.
- **Topology GPU free segments show the amount**: the "free" segment in the per-GPU lanes and the aggregate GPU bar now reads `free · {GiB}` (total minus used) instead of just `free`.
- **Topology pod names are click-to-copy**: clicking a pod name (in the CPU/Memory bar labels, the per-GPU lane segments, and the pod lists) copies its full `namespace/name` to the clipboard, for pasting into the CLI.
- **Serving placement row is a single line**: the node name, instance-type badge, GPU model badge, and per-card GPU UUID badges on each serving card now share one line — the node name truncates to fit and the badges stay (previously the row wrapped to a second line).
