# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- **Navigation: three areas instead of eight tabs**:
  - **Areas:** **Cluster** (Overview, Nodes, Topology, Disruptions), **Inference** (Serving, Gateway) and **Optimize** (Recommendations, Workloads), with the active area's pages as a second row. The Disruptions count shows on both the Cluster area and its page, and an area reopens the page you last had open in it.
  - **Paths:** pages have paths: `/cluster/topology`, `/inference/serving`, `/optimize/workloads` (the Overview stays at `/`). Nav items are real links, so middle-click opens a page in a new tab.
  - **Old links:** `?tab=` links keep working; they are rewritten to the new path with their focus and filters (`?tab=topology&node=x` → `/cluster/topology?node=x`). Unknown or partial paths go to the nearest real page.
  - **Logs drawer:** logs are a drawer, not a tab. The header **Logs** button, or a Logs link in Topology or Serving, opens the Log Explorer over the current page (`?logs=namespace/name`); closing it returns to where you were. The old `?tab=logs&pod=x` opens the drawer.
  - **Gateway page:** the LiteLLM gateway has its own page (Inference → Gateway) instead of sitting above the model servers; its view and split are URL params (`?view=models&split=team`).
  - **Tagline:** "Karpenter capacity and GPU inference operations".
  - **Routing:** `lib/routes.js` holds the scheme (areas, `parseLocation`, `buildUrl`) and is in the coverage gate. nginx already falls back to `index.html` for any path, so no deployment change is needed.

### Added
- **Topology: time travel**: a **History** button opens a timeline of the last day under the header.
  - **Replay** (`?at=`, shareable): every zoom level shows the cluster as it was at that moment, from where each pod ran to each GPU's tenants. Cost uses today's prices and there is no usage, which is "now" data.
  - **Compare with now** (`?compare=`): the live view stays and a panel lists what changed since then: launched nodes (green ring on the map), removed nodes (dashed red ghosts, grouped by Karpenter's reason such as Underutilized, Drifted or SpotInterrupted), pods that moved, and GPUs whose largest free slice shrank.
  - **Timeline markers:** node launches (green), terminations (red) and pod moves (amber) sit along the slider; hovering lists them, clicking replays that moment.
  - **How:** a sampler records nodes and pods every 2 minutes (`PLACEMENT_HISTORY_INTERVAL_SECS`) and keeps 24 hours (`PLACEMENT_HISTORY_HOURS`, max 72, 0 = off). It stores a full snapshot every 60 samples and only the changes in between (`internal/placementhistory`). The termination reason comes from Karpenter's Node events, read once per sample. History lives in memory and restarts with the pod; a durable store is a follow-up.
  - **API:** `GET /api/v1/topology/history?at=` and `GET /api/v1/topology/events?since=`.
- **Topology: drain simulator**: pick **Simulate drain** in any node's Actions menu, for one node or several (`?drain=a,b`, shareable). A panel answers "what happens if I drain these?":
  - **Moves:** where each pod would land, re-placed largest first on the remaining nodes, preferring the same NodePool and fitting CPU, memory and per-GPU memory (a fractional HAMi pod needs room on one card, a whole-GPU pod needs empty cards).
  - **Leftovers:** pods that would not fit anywhere are listed in red with the reason; DaemonSet pods go with the node.
  - **Saving:** the monthly saving from the nodes' prices.
  - **Display:** drained nodes are greyed out at every zoom level. The result is labelled approximate and lists what it does not model (taints, affinity, topology spread, PodDisruptionBudgets, Karpenter launching nodes). Read-only: nothing changes in the cluster.
- **Topology: placement planner**: the Will it fit? box gains a replicas field (`?replicas=2`).
  - **Placement:** the planner ranks GPUs by free memory on one card, then places replicas spreading across zones, then nodes, then onto the tightest card that fits.
  - **On the cards:** planned cards get R1, R2… badges.
  - **Verdict:** it says "fits across N nodes in M zones", warns when every replica would share one node or zone, and says when the pool must grow. Nodes in a drain simulation are not offered.
- **Topology code**: `TopologyView.jsx` drops from 552 to 410 lines: the node-card list moved to `NodeList.jsx`, data loading to `hooks/useTopologyData.js`, and the what-ifs to `hooks/useDrainPlan.js`.
- **Topology: requested vs used**: when a usage source is available, the Topology tab shows what pods actually use next to what they request. This is display only; recommendations keep their no-Prometheus rule.
  - **Sources:**
    - **metrics-server** is read automatically, giving live CPU and memory per pod. It is read through the existing Kubernetes client, so there is no new dependency.
    - **Prometheus**, when `PROMETHEUS_URL` (chart `usage.prometheusUrl`) is set, gives the p95 over 24h from cAdvisor, which is what rightsizing needs. It also gives GPU memory in use per card from the DCGM exporter (`DCGM_FI_DEV_FB_USED`).
    - Prometheus wins when both answer, and results are cached for 60s (`internal/usage`).
  - **In pod bars:** the requested-but-unused part of each pod's CPU or memory segment is hatched, and a pod using more than it requested gets a red edge.
  - **In GPU tanks:** a dashed line marks the memory actually in use, with the reserved-but-idle part above it hatched.
  - **Usage lens:** a new **Usage** lens colours nodes by used ÷ requested: violet for capacity asked for but idle, green for close to the request, red for over the request.
  - **Without a source:** the lens is hidden, and a note says the bars show requests only.
  - **API:** `/api/v1/topology` adds `usage` per pod plus top-level `usage` (`{source, window}` or `null`) and `gpuUsage` (UUID → MiB).
  - **Chart:** the ClusterRole gains read access to `metrics.k8s.io` pods and nodes.
- **Topology: blast-radius warnings**: workloads whose replicas all sit on one node, or all in one zone, are flagged, because a single drain, spot interruption or zone outage takes the whole workload down. The Cluster level shows the count (expandable, with links to the node), and the node card names the workloads that live only on it. DaemonSets, Jobs and single-replica workloads are left out, and spread is judged over all nodes, so a filter never fakes a risk.
- **Topology: node actions menu**: each node card has one **Actions** menu:
  - copy-ready `kubectl describe node`, pods-on-node, and `kubectl drain … --dry-run=client` (the app never changes the cluster);
  - the node's disruption status;
  - logs for any pod on the node (workloads first, DaemonSet agents last).
- **Topology: semantic zoom and lenses**: the Topology tab now opens on a **Cluster** map instead of a long list of cards. Every node is a tile, grouped by NodePool and zone and sized by allocatable CPU. Tiles shrink as the cluster grows: 200 nodes fit in two columns, and recolouring 1,000 nodes takes under 100 ms in Chrome, so plain DOM tiles are used rather than canvas.
  - **Levels:** clicking goes one level deeper: **NodePool** (larger tiles with CPU, memory and GPU request bars), **Node** (the node cards), then **GPU** (one tank, every slice named with its share of the card). Serving pods on a GPU show their health and link to their Serving card; every slice links to its logs.
  - **URLs:** each level has its own URL (`?zoom=pool&at=<pool>`, `?zoom=node&at=<node>`, `?zoom=gpu&at=<node>&card=<uuid>`) and its own history entry, so Back zooms out. A breadcrumb shows the path, and a minimap of the whole cluster stays in the corner below the Cluster level.
  - **Lenses** colour the tiles, with the legend always visible (`?lens=`): **Requests** (the tightest of CPU, memory and GPU), **Capacity type**, **Age**, **Cost** (per-node hourly price), **Serving health** (the worst serving status on the node) and **Disruption** (being disrupted or blocked). Serving and disruption data is fetched only when its lens is picked.
  - `/api/v1/topology` now includes `costPerHour`, `costSource` and `pricedAs` per node, from the existing pricing cache (`null` when unpriceable), plus a top-level `currency`.
  - A Serving → Topology link still opens the Node level focused on the pod; zooming elsewhere ends the focus.
  - `?tab=serving&pod=<ns>/<name>` now opens the Serving tab on that replica (row opened, card ringed).
- **Topology: GPU memory tanks and "Will it fit?"**: each GPU is now drawn as a vertical tank, with its pods' memory stacked from the bottom and free memory on top, replacing the horizontal per-GPU lanes. Below each node, one line states fragmentation: "109.4 GiB free, largest single gap 44.9 GiB". A **Will it fit?** box above the nodes takes a size ("40", "40 GiB", "24000 MiB"). It rings every card that has that much free on one GPU, fades the rest, and summarises "fits on 4 GPUs across 2 nodes" (or the largest free space when nothing fits). The size is kept in the URL (`?fit=40GiB`) so a check can be shared, and the summary follows the node filters.
  - Tanks count every GPU pod on the node, so a filter that hides a pod no longer makes its memory look free. Hidden pods are faded instead of dropped.
  - Cards no pod references are shown, and pods without HAMi placement are put on them. A whole-GPU pod takes a whole card. A fractional pod (`nvidia.com/gpumem`, no placement annotation) marks its card as uncertain, so the fit check counts that card as "may fit" rather than claiming room it isn't sure of. The check covers memory only (HAMi also limits cores and tasks per card).
  - Tanks show on any node whose GPU memory is known, HAMi or not; other nodes keep the GPU count bar. Focus links still outline the pod and its GPU neighbours.
- **Serving: cost per 1M tokens**: each model row shows an estimated self-hosted cost per million tokens: what its replicas cost per hour divided by the tokens they serve right now. A replica's hourly cost is its node's price (from the existing AWS pricing cache, spot-aware) times its share of the node's GPUs: HAMi placement memory over the node's GPU memory, or GPUs requested over the node's GPU count. When the model is in OpenRouter's public price list, the row also shows how this compares with the hosted price, blended by the model's own input/output token mix ("7.1× hosted $0.18"). A help popover lists every input. A model is only priced when every replica is, so a partial sum never understates the cost. Hosted prices are in USD, so there is no comparison in CNY regions.
  - `/api/v1/serving` gains, per pod: `cost` (`costPerHour`, `nodeCostPerHour`, `nodeCapacityType`, `share`, `shareBasis`, `currency`, `priceSource`; `null` when it can't be priced), `hostedPrice` (`source`, `model`, `inputPerMTok`, `outputPerMTok`, `fetchedAt`; `null` when unknown), `promptTokensPerSec` / `generationTokensPerSec`, `gpuRequested`, `nodeCapacityType` and `nodeGpuMemMiB`.
  - The OpenRouter catalog (`internal/hostedprices`) is fetched once a day, starting with the first Serving request that finds serving pods, so clusters without LLMs never call out. Models are matched by Hugging Face id, OpenRouter id or canonical slug (ignoring case; a base name also matches its `-instruct` variant). Free and variable-price entries are skipped. Without internet egress the fetch fails quietly: one log line, a retry every hour, and no comparison shown.
- **Serving: traffic headroom**: each model row estimates how much more traffic it takes before a replica's KV cache reaches 85%, from a linear fit of KV cache % against requests/s over each replica's serving history. The tightest replica sets the figure. It is hidden until there are 30 minutes of history, says why when it can't project (idle, KV not rising with traffic, or a weak fit), shows "none" when a replica is queueing or under KV pressure right now, and caps at +300%. The popover gives the fit and its assumptions.
- **Serving: grouped by model, with a triage list**: the Serving tab now shows one row per model instead of a flat grid of replicas. Each row has a dot per replica, coloured by status, and the model's health across replicas: replicas online, throughput and requests per second (summed), worst p95 TTFT and E2E, fullest KV cache, and running/waiting requests. Rows with a struggling replica start expanded and the others start folded; clicking a row overrides that. Clicking a replica dot opens its row, scrolls to its card and highlights it. When anything needs a human, a **Needs attention** list sits above the rows: one line per replica that is not OK, worst first, with its reasons (including who shares its GPU), how long the issue has lasted (from the trend history, using the same rules as the backend's last-issue marker), and three actions: **Topology**, **Logs**, and a **kubectl** menu with copy-ready `describe pod`, `logs --tail=200` and `describe node` commands. `?view=replicas` brings back the flat grid, and the sort selector applies to both views. The Model usage throughput ranking is gone, because the model rows cover it.
- **Deep links into the Log Explorer**: `?tab=logs&pod=namespace/name` opens the Log Analyzer on that pod. The Serving triage list's Logs action uses it, and the browser Back button returns to Serving.
- **Serving: problems first**: the Serving tab now sorts by **Needs attention** by default: offline, under pressure, busy, slow, then healthy (ties by throughput), so a struggling replica is at the top instead of the bottom of a throughput-sorted grid. Each status now carries a `severity`. The other sorts remain (`?sort=throughput` and so on), and existing links keep working.
- **Serving: latency split**: each card shows a bar splitting mean response time into time to first token (prefill: queueing and reading the prompt) and generation (decode), on a scale shared with the other replicas of the same model. A slow replica's bar is visibly longer, and the split says whether to look at queueing/prompts or at GPU contention/answer length. Means are used because they add up; p95s of the parts do not sum to the p95 of the whole.
- **Serving: help next to each metric**: every metric label has a `?` button that opens its definition (click, keyboard or touch), replacing the always-present "What do these metrics mean?" accordion and hover-only tooltips. The Running, Waiting and Preempt definitions now include what to do; the Trends panel explains what counts as an issue and how history is kept.
- **Shared polling clock**: every auto-refreshing panel (Overview, Nodes, Workloads, Disruptions, Serving, the Disruptions tab badge) now polls on one clock (`lib/pollingClock.js`, `usePolling`/`usePollingTick`) instead of its own `setInterval`. Panels fire on wall-clock-aligned boundaries of their interval, so panels with the same interval refresh together and describe the same moment; polling pauses while the browser tab is hidden and catches up once when it is shown again. The header shows when the data last refreshed ("Updated 11:42:05").
- **Filters in the URL**: Topology filters (metric, NodePool, zone, node, pod namespace and name, hide DaemonSets) and the Serving sort and trend window are kept in the URL, so a filtered view survives a refresh and can be shared. Filter changes replace the current history entry instead of adding one per keystroke; invalid values in a hand-edited URL fall back to the default.
- **Serving → Topology GPU noisy-neighbour links**: a struggling serving pod (busy, slow vs. its peers, or under KV-cache pressure) now names the pods that share its physical GPU, and its suggested fixes lead with moving them. The Serving tab reads `/api/v1/topology` (every 60s, non-fatal) and matches pods by HAMi device UUID; on a single-GPU node without placement data, other GPU pods are treated as time-slicing the same card. Problem cards show the diagnosis inline (reasons, a "Try first" fix, the remaining fixes in an expandable list) instead of only in a hover tooltip, and healthy pods that share a GPU get a quiet "Shares GPU … with N pods" chip. Every serving card links to **Show in topology**, which opens the Topology tab focused on the pod's node: a banner names the GPU neighbours (or explains that Karpenter has removed the node), filters are cleared, the node card is scrolled into view and outlined, the pod is outlined, and its neighbours on the same GPU are marked with a dashed outline. The status logic moved to `frontend/src/lib/servingStatus.js` and the placement matching to `frontend/src/lib/servingPlacement.js`, both covered by unit tests.
- **Shareable URLs for tabs**: the active tab and the Topology focus target are kept in the URL (`?tab=topology&node=…&pod=ns/name&gpu=…`), so views survive a refresh, can be shared, and the browser Back button returns from a Serving → Topology jump.
- **Generic cluster-wide Log Explorer** (replaces the Karpenter-only analyzer): pick any pod in the cluster and read/analyze its logs. New endpoints behind the standard `/api/v1` auth: `GET /api/v1/pods` (compact pod summaries — status, readiness, containers, restarts, Karpenter flag — for the picker), `GET /api/v1/pods/logs?namespace=&pod=&container=&tailLines=&sinceSeconds=&previous=` (any pod/container, no Karpenter gate — the dedicated `GET /karpenter/logs` keeps its `app.kubernetes.io/name=karpenter` gate), and `POST /api/v1/logs/analyze`, which parses a Karpenter JSON log line with the existing Karpenter analyzer first and otherwise runs a **generic** analyzer: an LLM explanation when configured, else a built-in heuristic classifier (OOM, image pull, crash loop, permission/admission, network/dependency, disk pressure, app panic, generic error) with per-pattern recommendations. The frontend is a new `LogExplorer` (pod picker with Karpenter presets, container/tail/since/previous controls, client-side error filter, search with match highlight + prev/next, and Analyze selection / last-N / all-errors buttons) that replaces `KarpenterLogAnalyzer`.
- **Opt-in API authentication** (`API_AUTH_TOKEN`): when set, every `/api/v1` route except `/health` (k8s probes) and, when enabled, `/metrics` requires `Authorization: Bearer <token>` (constant-time compare). Unset = legacy open API with a startup warning — zero migration pain, hardening is opt-in. Chart: `config.apiAuthTokenSecret` (existing Secret, key `api-auth-token`) or `config.apiAuthToken` (dev-only plain). The frontend container receives the same token as `REACT_APP_API_TOKEN` via the runtime `config.js` (never baked into the bundle) and sends it through an axios default header, so enabling auth does not 401 the UI.
- **Chart secrets for credentials**: `LLM_API_KEY` (`config.llm.apiKeySecret`, key `api-key`) and alert channel URLs (`alerts.urlsSecret`, key `urls`) are now delivered via `secretKeyRef` so they are not visible in the pod spec / etcd. Plain `config.llm.apiKey` and `alerts.urls` remain as documented dev-only fallbacks.
- **Graceful shutdown**: the API now runs under `signal.NotifyContext(SIGINT, SIGTERM)` with `http.Server.Shutdown` (10s drain) instead of a blocking `gin` run; background samplers take a root cancellable context and the durable Postgres pools (`gatewayhistory`, `servingdurable`) are closed on shutdown.
- **Alerting engine** (opt-in): a background evaluator runs on each 60s sampler tick and watches five conditions — **cost spike** (cluster cost/hour up >X% vs its trailing 24h average), **blocked disruption** (a node stuck blocked for >N min), **serving under pressure** (KV cache ≥X% held for the `for` duration), **gateway** (503 rejections or error rate above threshold), and **serving pod offline**. Each condition drives a `pending → firing → cleared` state machine with a held-clear window so flapping does not spam; the firing set is **persisted to disk** so restarts neither re-fire nor drop in-flight alerts. New transitions fan out (one message per channel per transition) to **ntfy** (topic URL + priority/tags), **Discord** webhook, **Slack** incoming webhook, or a **generic JSON webhook** (`{source, status, severity, title, alerts[]}`); an optional `remindWhileFiring` (1h/4h/12h/24h) re-notifies while an alert stays firing. All outbound URLs are **SSRF-validated** (http(s) only, no redirects, no response bodies logged, resolve-then-pin, refuse link-local/metadata/multicast) and treated as **credentials** — `GET /api/v1/alerts/config` masks channel URLs (host kept, path redacted to `/*`) and `PUT` restores the stored URL by index so toggling a condition never wipes a secret. New endpoints: `GET/PUT /api/v1/alerts/config` and `POST /api/v1/alerts/test`. Chart values `alerts.enabled` + `alerts.urls` (or via the API), `alerts.stateFile`. Defaults to a conservative all-disabled config.
- **Prometheus `/metrics` exporter** (opt-in): a `GET /metrics` endpoint (text-0.0.4 via `client_golang`) serving `karpenter_optimizer_*` gauges — `up`, `kubernetes_connected`, `karpenter_detected`, cluster nodes/pods/CPU/memory used & allocatable, cost/hour, power watts, per-NodePool `nodepool_nodes` + `nodepool_cost_per_hour`, per-serving-pod online/KV-cache/TTFT-p95/E2E-p95/tokens-per-sec/requests-per-sec, gateway in-flight/queued/rejected/error-rate/requests-per-sec/spend-total/per-app-spend, and disruptions active/blocked/cost-per-hour. Data comes from an **atomic snapshot refreshed by the existing samplers** (cluster, serving, gateway, alert ticks), so a scrape performs **zero** extra Kubernetes or AWS Pricing API calls. Gated by `METRICS_ENABLED` (chart value `metrics.enabled`); the route is not registered and `/metrics` 404s when off. The chart's optional `serviceMonitor` scrapes `/metrics` when both `serviceMonitor.enabled` and `metrics.enabled` are set.
- **Durable serving history** (opt-in): per-pod serving samples are now optionally persisted to **Postgres/CNPG** in a new `serving_history` table (`(pod_key, t)` upsert, retention index, retention purge) when `SERVING_HISTORY_DSN` — or the existing `GATEWAY_HISTORY_DB_HOST/PORT/USER/NAME/PASSWORD` parts (reuse one CNPG instance) — is set. The in-memory `servinghistory.Store` stays the fast path for the 1h/6h/24h sparklines; the durable store serves the new **7d** trend window (closed period read from Postgres, today merged from live samples, in-memory points winning on overlap). `GET /api/v1/serving/history` gains `window=7d` when the durable store is active, otherwise windows remain in-memory. Chart values `servingHistory.durable` + `servingHistory.retentionHours`. Also fixed `parseGatewayHistoryWindow`/`parseServingHistoryWindow` to accept `Nd` day windows (`7d`/`14d`/`30d`).
- **sparkDash-grade visual polish** (light scope):
  - **Dark/light theme** (4a): a sun/moon toggle in the header persists to `localStorage`, defaults to system preference via `matchMedia`, and `index.js` applies the `dark` class to `<html>` **before first paint** (no flash). A token audit replaced hardcoded light-only utilities (`bg-white`, `text-blue-600`, `border-gray-*`, `bg-purple-100`, `text-gray-900`, …) with semantic tokens (`bg-card`, `text-primary`, `border-border`, `text-foreground`, `bg-muted`) across the header/nav, cards, tables, and the gateway/serving components.
  - **Shell/nav polish** (4b): the 8 copy-pasted tab buttons were extracted into a `NavItem` component with a lucide icon per tab (Overview, Nodes, Topology, Serving, Workloads, Disruptions, Recommendations, Logs); the active tab keeps the `primary` underline with a `hover:bg-muted/40` state, a **live disruptions count badge** appears on the Disruptions tab, and `<main key={activeTab}>` runs a subtle fade/slide-in page transition.
  - **Empty/loading states** (4c): a shared `EmptyState` (icon + title + hint + optional retry) and `Skeleton`/`SkeletonRows` (radix-free pulse divs, no layout shift) now replace ad-hoc "no data" strings and generic spinners across GlobalClusterSummary, NodeUsageView, WorkloadUsageView, TopologyView, DisruptionTracker, AgentRecommendations, KarpenterLogAnalyzer, and ServingHealth — error banners carry a retry button.
- **LiteLLM Gateway cost & token history** (Serving tab): per-day spend and token usage for the LiteLLM gateway, so you can follow cost trends over time instead of only seeing cumulative totals. Days are **UTC (00:00–23:59)** and the UI is a **usage-by-day dashboard**: a **stacked per-day bar chart** (one bar per day, split by the active **Split by** dimension — app / API key / team — with a spend/tokens toggle and an optional daily-total line) plus a **per-day table** (day / spend / tokens / top consumer, today marked "so far"). A background sampler (same 60s interval as the cluster/serving trend samplers) diffs the gateway's cumulative spend/token counters each tick and folds the deltas into per-day totals in the store — **incremental rollups, no midnight job**: once a day passes its row is final and is only ever read from the store (the gateway is never re-queried for closed days), and today updates live. The chart is **interactive**: series are colored on a single-hue violet ramp **ranked by usage** (darkest = biggest consumer), and hovering a series (bar segment or legend chip) highlights it across all days with a soft gradient area under its evolution curve, dims the other series, and opens a **rich tooltip** (series value, % of day, % of window, day total) plus a **live stat strip** (window total, share, avg/day, today-vs-average delta); the chart legend is a row of **pill chips** with each series' window share, and clicking a chip pins the highlight. New endpoint `GET /api/v1/serving/gateway/history?split=total|app|apikey|team&window=14d` returns `{window, split, store, days[]}` (each `day` has `value` + `spend` + `tokens`, ordered by day; 7/14/30-day window selector). Counter resets (a gateway replica restart) clamp the interval diff to 0 rather than reporting a spike (the day is an honest under-count).
  - **Storage**: in-memory by default (resets on process restart), or a durable **Postgres/CNPG** store when `GATEWAY_HISTORY_DSN` (or the `GATEWAY_HISTORY_DB_HOST/PORT/USER/NAME/PASSWORD` parts) is set — the Helm chart provisions a small CNPG `PostgresCluster` when `database.enabled: true`, making history survive restarts/redeploys (and enabling multi-replica consistency). Retention via `GATEWAY_HISTORY_RETENTION_HOURS` (default 720 = 30 days). Requires the CNPG operator to be installed when enabled; if the DB is unreachable the app falls back to in-memory so the gateway UI is never blocked.
- **AWS China-region pricing**: AWS Pricing API queries now support `cn-north-1` and `cn-northwest-1` through the China partition endpoint, using the correct regional product location and CNY pricing. `/api/v1/config` exposes the configured AWS region and pricing currency, and pricing/recommendation responses include currency metadata for display.
- **Currency-aware cost display**: Cost figures throughout the UI now use the configured region's pricing currency (`CN¥` for China regions, `$` otherwise), including cluster summaries, recommendations, node usage, agent output, and disruption costs.
- **China pricing fallback snapshots**: Dated CNY fallback prices are used for supported China-region instance types only when live pricing is unavailable due to transient/API access failures; explicit no-product results are not masked by estimates. Pricing source metadata identifies regional fallback estimates.
- **Regional Pricing API routing**: Pricing requests prefer a global endpoint geographically suited to the target region (US, Europe/Middle East/Africa, or Asia-Pacific) and retry other global endpoints for transient failures while preserving the target product-location filter. China requests stay within the China partition. Pricing-index lookups also use region-appropriate hosts and filter results to the configured region.

### Changed
- **Serving no longer downloads the topology**: GPU neighbours are computed by the backend and returned with each serving pod (`gpuNeighbours`, `gpuNeighboursPrecise` on `/api/v1/serving`), using the same rules as the Topology view (HAMi device UUID, or time-slicing on a single-GPU node). The Serving tab drops its 60-second `/api/v1/topology` poll, which returned every node and pod in the cluster. The backend lists pods only on the nodes hosting serving pods, only for the endpoint (the history sampler is unaffected), and leaves the field `null` if the list fails, so the UI never claims a pod is alone when it doesn't know.
- **One dropdown component**: the six native `<select>` elements (Topology NodePool and zone filters, the alert reminder and channel-type pickers, the gateway history window) now use the shared Radix-based `SimpleSelect`, so every dropdown has the same look, keyboard behaviour and dark-mode styling. `SimpleSelect` handles "All"/"Off" options stored as empty strings, which Radix otherwise rejects.
- **Leaner card headers**: Serving cards show one status badge (the separate "online" badge is gone; offline is itself a status), with backend, instance type and GPU model in a quiet metadata line. Topology and Nodes node cards keep only the GPU summary badge and move instance type, capacity type, zone, architecture, NodePool and age into the same metadata line. Both node views now share one `GpuSummaryBadge` and one `PricingSourceLabel` instead of duplicated code.
- **Icons instead of emoji**: 🎮, 📦, 🌍, 📊, ✨ and the ✓/⚠ pricing markers are replaced with lucide icons.
- **Removed dead code**: five components nothing imported (`WorkloadSelector`, `WorkloadForm`, `ComparisonView`, `RecommendationCard`, `ClusterSummary`) and `App.css`, whose classes were unused and whose hard-coded light `body` background showed through on overscroll in dark mode.

### Fixed
- **Serving: old preemptions marked healthy servers "Under pressure" forever**: `preemptions` is vLLM's lifetime counter (`num_preemptions_total`), but the status badge and the trends' "last issue" treated any value above 0 as current pressure. A replica preempted once, days ago, stayed red, and its last issue always read "just now". The prober now also reports `preemptionsRecent` (the counter's increase over the last 5 minutes, measured by time so it doesn't depend on probe frequency, and robust to restarts), and the status uses it. History counts a preemption only when the counter grows between online samples (`servinghistory.LastIssueIn`, now shared by the in-memory and durable paths instead of two copies). The Preempt tile shows the last 5 minutes, with the lifetime total below it.
- **Topology listed every pod once per node**: `GetPodsOnNodes` asked for each node separately, and because field selectors take one `spec.nodeName`, each request listed the whole cluster's pods. A 200-node `/api/v1/topology` call made 200 full pod lists. It now makes one paginated list and groups it by node (same data, same filters). It also returns an error instead of silently skipping nodes when the list fails; `/topology` and the NodePool workload lookup already handle that error.
- **Serving sort label cut off**: the Sort dropdown was too narrow and showed "Sort:..."; it now fits its longest option.
- **Missing React keys on GPU lanes**: `GPULaneBar` rendered its per-GPU rows without keys (a console warning, and React could mismatch rows when GPUs changed); each row is now keyed by its GPU UUID.
- **`npm ci` failed on a clean checkout**: `frontend/package-lock.json` was missing `yaml@2.9.1`. The lockfile is regenerated, and CI and the frontend Docker image now install with `npm ci`, so an out-of-sync lockfile fails the build instead of being silently rewritten.
- **One API base URL**: the API base URL was resolved in 12 separate files (two different ways); it now comes from `lib/api.js`, which also installs the optional `API_AUTH_TOKEN` bearer header.
- **API test harness leak**: `setupTestServer` built a `Server` against the developer's real `~/.kube/config` and left background samplers running across tests; they read `s.k8sClient` (and the package-global LiteLLM prober) while other tests reassigned it — a data race surfaced under `-race`. The helper now starts a hermetic server (no cluster, no samplers).
- **`RecordOutcome` self-deadlock** in `internal/agent/learning.go`: the method held `historyMu.Lock()` while `saveHistory()`/`learnFromOutcome` re-took the same non-reentrant mutex, hanging the first `POST /agent/outcomes` forever. Persistence and learning now run outside the write lock (regression tests with timeouts in `internal/agent/learning_test.go`).
- **Release workflow clobbering the CNPG Postgres image tag**: `sed` over every `tag:` in `values.yaml` rewrote `database.cluster.postgresImage.tag` on the next release. App image tags are now bumped by repository-anchored replacement with a `postgresImage.tag` guard.
- **Swallowed pricing errors manufacturing fake savings**: pricing failures previously summed as `Cost: 0`, understating totals and faking savings (and skewing the cost-spike alert baseline). `/nodepools`, `/cluster/summary`, `/recommendations` (JSON + SSE), `/recommendations/cluster-summary`, and the history sampler now surface `costUnknown` when any node in a summed set is unpriceable; the cost-spike alert treats unknown-cost samples as no-data.
- **Cluster-wide pod-log dump**: `GET /api/v1/karpenter/logs` now requires the target pod to carry `app.kubernetes.io/name=karpenter` (403 otherwise), closing the hole left by the broad `pods/log` RBAC grant.
- **CORS wildcard + credentials anti-pattern**: removed `Access-Control-Allow-Credentials: true` combined with `*` (browsers reject it). Same-origin by default; optional single `CORS_ALLOWED_ORIGIN` for split deployments.
- **Per-request learning-agent construction**: the cost-optimization `LearningAgent` is now a process singleton (`sync.Once`), eliminating per-request history-file I/O, leaked initial `learnFromHistory` goroutines, and uncoordinated concurrent writes to `AGENT_HISTORY_FILE`.
- **Region-specific pricing estimates**: The `us-east-1` USD hardcoded/family estimates are no longer applied to other commercial regions or China. China costs are not presented using USD estimates, and unknown prices no longer silently understate mixed-instance totals as partial costs.
- **China fallback candidate availability**: Instance-type fallbacks now exclude families without regional China availability and include available AMD instance types when they are appropriate candidates.
- **Pricing-index architecture filtering**: AMD64 instance discovery now relies on AWS Pricing `processorArchitecture` metadata instead of instance-name substring matches, preventing x86 types such as `m6i.large` from being incorrectly excluded.
